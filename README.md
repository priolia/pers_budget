# 💰 Персональное бюджетирование

Однопользовательское веб-приложение для ведения месячного бюджета с привязкой к нестандартному «зарплатному» месяцу, поддержкой нескольких валют и учётом резервных накоплений отдельно от основного потока.

🔗 **[priolia.github.io/pers_budget](https://priolia.github.io/pers_budget/)**

> Версия 2.2 Auth Update (май 2026). Личный проект.

---

## Возможности

**Гибкий период.** Месяц считается не календарно, а от выбранного «дня зарплаты» — например, с 25-го одного месяца по 24-е следующего. Селектор периода динамический: один предыдущий, текущий и двенадцать вперёд, плюс отдельная группа архива для исторических периодов.

**Категории с двойным управлением лимитом.** Лимит задаётся в евро или процентом от дохода — что задаёшь, то ведущее, второе пересчитывается. У каждой категории — эмодзи-иконка (предлагается автоматически по словарю), настраиваемый порядок, флаг участия в дневном расходе и флаг «пополняет запас».

**Копилки.** Деньги «за пределами» месячного бюджета — отдельная сущность с собственным балансом в EUR или UAH. У каждой траты есть источник: месячный доход или конкретная копилка. Крупные незапланированные расходы (медицина, ремонт) можно покрыть из копилки — они учтутся в годовой статистике, но не испортят картину месяца.

**Дашборд бюджета.** Три ключевые карточки сверху (дни до конца периода и свободная сумма, процент исполнения, дневной лимит по выбранным категориям) и таблица с план/факт/остатком и расчётом «евро в день» на оставшиеся дни.

**Мультивалютность.** Доход и лимиты в EUR, операционные траты — в EUR или UAH. Курсы обновляются автоматически с Monobank API.

**Расчёт налогов для ФОП.** Отдельный блок: месячный и квартальный налог в гривнах, база — минимум из фактического дохода и лимита ФОП.

**Импорт-экспорт.** Полный дамп данных в JSON, экспорт трат и категорий в CSV, отчёт по периоду в HTML.

**Авторизация.** Вход только через Google Sign-In с whitelist email на двух уровнях (Google Test Users + серверная проверка).

**Адаптивность.** Мобильная вёрстка с залипающей колонкой описания при горизонтальном скролле длинных таблиц.

## Технический стек

**Фронтенд** — ванильный JavaScript на ES Modules, без сборщика и без TypeScript. Chart.js через CDN для визуализации. Google Identity Services для авторизации. Размещён на GitHub Pages.

**Бэкенд** — Flask на Python, хранение данных в JSON-файлах с автоматическим бэкапированием. Развёрнут на VPS (HostHatch, Ubuntu) под systemd. Nginx как reverse proxy, Let's Encrypt для HTTPS, DuckDNS для домена.

**Интеграции** — Monobank API (курсы валют), Google OAuth (авторизация по ID-токену с серверной проверкой подписи).

## Архитектура

**Модульный фронтенд.** Логика разнесена по самостоятельным ES-модулям: отдельно UI-слой, отдельно работа с данными, отдельно API-клиент, отдельно авторизация, синхронизация и миграции. Утилиты валют, дат, импорта/экспорта — в подпакете. Без зависимости от фреймворков и сборщика — `<script type="module">` напрямую в HTML.

**Локальное состояние + серверная синхронизация.** Все операции работают локально и моментально через локальный стейт; синхронизация с сервером — фоновая, с автоматическим разрешением при подключении. Локальное хранение позволяет открывать приложение без интернета (с ограничениями функциональности).

**Двухслойная авторизация.**
1. Google Identity Services выдаёт ID-токен с email-ом пользователя только из списка Test Users, настроенных в Google Cloud Console.
2. Сервер при каждом запросе проверяет подпись токена через библиотеку `google-auth`, верифицирует флаг `email_verified` и сверяет email с whitelist в серверной конфигурации.

Токен хранится в `sessionStorage` и автоматически инвалидируется при 401/403 от сервера.

**Резервное копирование.** Бэкапы создаются автоматически на каждое изменение данных с retention 7 дней и лимитом 20 файлов на тип. Технические обновления (только курсы валют) бэкапы не создают, чтобы не плодить мусор.
